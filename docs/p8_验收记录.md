## 交付物

- `backend/core/alerts.py`:6 条预警规则(睡眠债/过训/体重波动/体重骤变+就医提示/记录中断/完成率低),纯函数
- `backend/core/reporter.py`:简报/周报生成(规则算事实 + LLM 只组织;**LLM 失败降级模板文本**)
- `backend/core/jobs.py`:四类任务(打卡提醒/每日简报/周报/异常预警),全部 `msg_key` 幂等 + 触发前实时复检
- `backend/core/scheduler.py`:APScheduler 网关进程内(决策 D3);时间读画像 `remind_times`(缺省 20:00 / 21:30 / 周日 21:00 / 09:00);启动失败只降级
- `backend/core/notify_store.py`:站内信/报告存取(msg_key 唯一)
- REST:`GET/POST /messages`(列表/未读数/标记已读)、`GET /reports`、`POST /jobs/run`(演示手动触发,`JOB_TRIGGER_ENABLED` 可关)
- 前端:「**报告与提醒**」页(站内信按类型着色 + 全部已读;报告折叠列表)+ 侧边栏**未读红点**(事件总线刷新)
- `scripts/check_notify.py`(14 断言,结束自动复原数据)
- `tests/test_alerts.py`(10)、`tests/test_jobs.py`(8,含幂等/48h 防重/降级/时间解析)

## 实测证据(真实链路)

```
[OK] 调度器运行中(true)
[OK] 打卡提醒 sent(实际 sent)→ 复放 duplicate
[OK] 每日简报 sent + 报告落库 → 复放 duplicate
[OK] 周报 sent
[OK] 低睡眠 → sleep_debt 预警(实际 ['sleep_debt', 'weight_fluctuation'])
[OK] 预警复放不重复
[OK] 未读站内信 5 条 → 单条已读(-1)→ 全部已读(0)
[OK] 周报/简报可查
```

> 备注:预警验收还额外命中了 `weight_fluctuation`——演示数据最近一周体重 67.2→68.2(1.49%),规则真实生效。

## 设计要点(面试口径)

- **幂等键 = 类型+日期(+规则)**:重复触发/补跑不会轰炸用户;预警同规则 48h 防重
- **触发前复检**:一切以实时查询为准("计划已打卡就不提醒");避免"数据过期还打扰"
- **降级不阻塞**:调度器起不来、LLM 挂了都不影响对话主链路;报告自动退化为规则模板
- **时间可配置**:提醒时间来自画像页(用户改了就生效,重启后重读)
