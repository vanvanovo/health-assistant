## 交付物

- `backend/agents/common/`:states.py(三图状态)/ result.py(统一结果契约)/ llm_json.py(JSON 抽取+重试)/ tools.py(MCP 调用封装)/ utils.py
- `backend/agents/recorder/`:parse(LLM 抽取)→ validate(范围/日期校验)→ clarify / upsert(MCP)→ confirm(确认卡)

- `backend/agents/planner/`:context(画像+统计+事件)→ adjust(调档规则)→ generate(LLM 硬约束)→ save(版本化+幂等)→ plan 卡

- `tests/`:test_common(5)/ test_recorder(8)/ test_analyst(8)/ test_planner(9)/ test_llm(+2 异步)/ test_stats(4)→ **42 个**

## 关键设计(面试口径)

1. **规则算事实、LLM 只解读**:统计/异常/调档全部纯函数,LLM 只做抽取、解读与组织;提示词硬约束"只引用给定数据"。
2. **追问 ≠ 失败**:记录缺关键字段(体重)→ `status=clarify`,是正常业务态;测试断言"追问时不写库"。
3. **计划不是一次生成**:完成率/体感 → 强度档(up/keep/down);出差→轻量日;伤病→规避;事件来自记忆表的有效期过滤。
4. **可解释的拒绝**:LLM 输出的计划项在本地二次校验(kind/日期/强度越界直接拒绝),不合法就不落库。
