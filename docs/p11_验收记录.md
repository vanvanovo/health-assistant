## 过程中发现并处理(面试素材)

1. **构建慢 = 网络**:卡在 Docker Hub 拉基础镜像(非报错);手动 pull 热身后续阶段秒过。Docker Hub 慢但可用,当前无需代理。
2. **冷启动贴超时线**:迁移到容器链路后,首次知识问答因 BGE-M3 冷加载耗时 14.5s(逼近 A2A 15s 超时)。修复:**RAG Agent 启动预热嵌入模型**(实测 warmup 2s,后续问答 3.8~5.5s)。
3. **排障插曲**:两次"界面卡在正在输入"均为自动化检查/截图时机早于流结束;nginx 访问日志(响应完整 200、字节数正常)与最终页面渲染证明**链路无缺陷**——最终以浏览器截图与 39/39 回归收口。

## 云端轻量部署(2026-10-07 补充验收)

> 服务器:阿里云 Ubuntu 24.04.4 LTS · 2 核 · 1.7G 内存 · 40G 盘(SSH 别名 `120srv`)
> 公网入口:**http://120.27.141.121:8080**(阿里云安全组放行 8080;系统 Nginx :80 既有站点保持不动)

| # | 项 | 结果 | 证据 |
|---|---|---|---|
| 1 | Docker 环境 | ✅ | docker 29.1.3 + compose 2.40.3(apt);镜像加速 daocloud/dockerproxy(redis 镜像 **5.4s** 拉完);加 2G swap |
| 2 | 云端编排 | ✅ | 独立文件 `docker-compose.cloud.yml`:PG/Redis/网关**不发布宿主端口**(仅容器内网),公网仅前端 :8080;`RAG_VIA_A2A=false`;网关 `TZ=Asia/Shanghai` |
| 3 | 部署方式 | ✅ | 源码 tar 仅 0.14MB → `/opt/health-assistant`;镜像在服务器端构建(网关 + 前端) |
| 4 | 运行态 | ✅ | 4 容器全 Up;健康 JSON:`memory=postgres, scheduler=true, llm_providers=[deepseek, deepseek-fallback]` |
| 5 | 内存占用 | ✅ | postgres **31MB** / redis **3MB** / gateway **317MB** / frontend **13MB**;系统 available ≈ 0.97GB(1.7G 够用) |
| 6 | 公网冒烟 | ✅ | `scripts/check_cloud.py` **14/14**:未登录 401 / 登录 / 规则前置 / 知识降级(标注"知识库暂不可用",meta.degraded=True)/ 高危拦截(120 + 就医引导,meta.safety=high)/ 记录回执卡 / 看板 / 画像 |
| 7 | 时区修复 | ✅ | 容器默认 UTC 会让 `date.today()` 跨日偏差 → 网关加 `TZ=Asia/Shanghai` 重建(容器内 `date` = CST) |

**过程中发现并处理(面试素材)**:

1. **1.7G 跑不动 BGE-M3** → 云端不部署 RAG Agent,知识问答走已实测的降级链路(明确标注,不冒充知识库)。
2. **Docker 发布宿主端口反复 `address already in use`**(端口实际空闲,重启引擎/清网络后仍偶发)→ 改为云端**不发布内网端口**(PG/Redis/网关),顺带更安全,问题根除。
3. **容器时区**:UTC 容器里 `date.today()` 在北京时间 0–8 点会算成"昨天"(影响种子数据与 4 类主动服务触发点)→ `TZ=Asia/Shanghai` 修复。
4. 演示数据策略:`SEED_DEMO=true` 容器重建即重灌(演示友好);公网只放演示数据。
