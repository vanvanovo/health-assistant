## 设计要点(面试口径)

1. **Redis 只做三件事**:看板缓存 / 路由缓存 / 写锁——"按需引入,不做过度设计";不做发布订阅、不堆指标
2. **降级优先于可用**:缓存/锁全部"失败即旁路",主动服务与对话主链路在 Redis 挂掉时行为不变
3. **带上下文不缓存**:多轮指代的语义依赖 history,缓存会串味——这是一个真实的"缓存边界"设计点
4. **降级窗口 30s**:Redis 故障时避免每次请求都去重连(1s 超时 ×N)
