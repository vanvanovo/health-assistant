## 三、P8 主动服务(约 1~1.5 天)

### 3.1 调度与四类任务(APScheduler 跑在网关进程内,决策 D3)

| 任务 | 触发(读画像 `remind_times`,缺省如下) | 内容 | 防重 |
|---|---|---|---|
| 打卡提醒 | 每日 20:00 | 今日未完成计划项 + 预计时长 | `msg_key = remind:{date}` |
| 每日简报 | 每日 21:30 | 今日完成度 + 明日安排 + 一句建议 | `brief:{date}` |
| 周报 | 每周日 21:00 | 数据事实 + 亮点/不足 + 下周建议(存 reports) | `weekly:{week_start}` |
| 异常预警 | 每日 09:00 + 简报前巡检 | 命中规则即报(见 3.2) | `alert:{rule}:{date}`(同规则 48h 防重) |

- **触发前复检**:提醒/预警生成前重新查询当日数据(如计划已打卡、事件已过期 → 不打扰)
- **站内信**:`messages` 表已有(msg_key 唯一约束 = 幂等);写站内信即完成"触达"
- **降级**:调度器启动失败或 LLM 不可用 → 只发规则版简报(模板文本),不阻塞

### 3.2 预警规则表(纯函数 `core/alerts.py`,可单测)

| 规则 | 阈值(演示口径) | 级别 |
|---|---|---|
| 睡眠债 | 连续 2 天睡眠 <6h | warn |
| 体重波动 | 一周变化 >1% | warn |
| 过训信号 | 连续 3 天高强度(>=50min 或 strength)无休 | warn |
| 记录中断 | 7 天未记录 | info |
| 完成率低 | 近两周计划完成率 <40% | info |
| 体重骤变 | 一周变化 >2% | 附「建议咨询医生」提示 |

### 3.3 简报 / 周报生成(`core/reporter.py`)

- 数据事实:MCP `get_range_summary` / `get_plan_progress` / `get_day_intake`(规则口径)
- LLM 只做组织:硬约束"只能引用给定事实";失败降级为模板文本
- 落库:`reports`(type=daily/weekly)+ 站内信(带 `report_id` 便于跳转)

### 3.4 站内信 + 报告中心(API + 前端)

- REST:`GET /api/v1/messages?unread=`、`POST /api/v1/messages/{id}/read`、`GET /api/v1/reports?type=&limit=`
- 前端新增「报告与提醒」页(两个 Tab:站内信 / 报告);侧边栏**未读红点**(进入页面后清零)
- 消息类型图标:提醒/简报/周报/预警四色标签

### 3.5 演示与验收用手动触发端点

- `POST /api/v1/jobs/run`(JWT;参数 `job=remind|brief|weekly|alert`、`date` 可选;开关 `JOB_TRIGGER_ENABLED`,默认开,demo 用)
- 用途:验收脚本无需等到 20:00/周日,即可复现四类消息 + 幂等复放

### 3.6 测试与验收

- 离线 ≥12:预警 6 条规则边界、msg_key 幂等、触发前复检(计划已打卡不提醒)、简报模板降级、reporter 事实约束
- `scripts/check_notify.py`(真实链路:手动触发四类 → 断言站内信/报告落库 → 复放幂等 → 未读/已读流转 → 复原数据)
- E2E 增加:场景 7 打卡提醒/简报、场景 8 周报、场景 9 预警(连续熬夜构造)

**门禁**:✅ 已完成(2026-10-06):`check_notify` **14/14**;四类幂等复放;触发前复检(skipped 用例过);预警 10 单测;E2E **34/34**;离线 **115 全绿**。详见《p8_验收记录》。

## 四、P9 健康知识 RAG + 安全边界(约 1.5~2 天)

### 4.1 知识库与建库(pgvector,BGE-M3)

- 语料 `data/kb/*.md`(实际:**8 篇长文 → 40 个知识块**,检索以块为单位;文档数少于原估 30~50"篇",块数在目标区间——如实记录):运动训练(热身/强度/低冲击替换)、营养(宏量需求/减脂增肌/常见食物)、睡眠恢复(睡眠卫生/过训信号)、**安全边界(何时应就医/免责声明)**
- `scripts/build_kb.py`:分块(按标题/长度)→ BGE-M3 嵌入(本地 CPU;权重路径实施时勘察,复用 cs-platform 已下载模型)→ 写 `kb_docs/kb_chunks`(vector(1024));幂等重建
- 检索:`kb_chunks` 向量 Top-K + 关键词过滤;**Retriever 抽象**:`pgvector`(默认)/ `none`(纯 LLM),配置切换

### 4.2 A2A 独立 RAG Agent(:5021,复用 cs-platform 已验证骨架)

- `services/rag_agent/server.py`:python-a2a `A2AServer` + `AgentCard`(skills: `health_kb_search`)+ `handle_task`
- 流程:retrieve → prompt("只引用检索内容;不给医疗诊断") → LLM 生成 → 返回 `{answer, sources[], answer_mode, safety}`
- **降级**:RAG 关停/超时(15s 实测口径)→ 主控 `answer_mode=llm_direct` + `meta.degraded=true` + 话术注明"知识库暂不可用,以下为通用建议"
- 主控侧:阈值 `RAG_VIA_A2A` 开关 + A2A 客户端(电子化超时/状态解析,复用 cs-platform `a2a_client` 思路)

### 4.3 安全边界(轻量三件套,决策 D5)

1. 免责声明:知识问答与建议类回答落款"仅供参考,不构成医疗建议"
2. 硬约束:prompt 禁止诊断/开药/治疗方案;知识库不放疾病治疗内容
3. 高危拦截:`core/safety.py`(关键词表 + LLM 判定)→ 命中即停止建议、输出就医/急救引导、`safety.level=high`、写安全日志
   - 高危示例:胸痛、晕厥、呼吸困难、持续剧痛、自伤念头
   - **用例 ≥10 条**(正常不误拦 / 高危必拦 / 边界走谨慎提示)

### 4.4 接入主链路

- `knowledge` 意图实做(替换"即将上线"占位):`_dispatch("knowledge")` → A2A RAG(降级 llm_direct)
- 新增卡片 `sources`(来源列表)与 `safety` 标注(meta.safety);前端 CardBlock 渲染
- 路由提示词微调:knowledge 去掉占位说明;与 diet/memory 的边界示例

### 4.5 测试与验收

- 离线 ≥12:安全用例表驱动(10+)、检索抽象(none 降级)、sources 组装、A2A 契约解析、超时降级
- `scripts/check_rag.py`(真实链路:直连 A2A 问答带来源;关停 Agent → 主链路只降级;高危问题 100% 拦截;复原数据)
- `scripts/eval_rag.py`:30+ 问答对 → 命中率、来源率、faithfulness 抽样(LLM-Judge 打分);报告落 docs/
- E2E 增加:场景 10 知识问答(带来源)与越界拦截

**门禁**:✅ 已完成(2026-10-06):`check_rag` phase1 **10/10** + phase2(关停降级)**4/4**;安全 12 用例;RAG 评测 **30/30 命中 · 100% 来源 · 100% faithfulness**;E2E **39/39**;离线 **141 全绿**。过程修复 3 个问题(检索标题粒度 / 候选窗口+混合重排 / 安全关键字变体),详见《p9_验收记录》。
